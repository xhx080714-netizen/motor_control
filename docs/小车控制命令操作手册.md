# 小车控制命令操作手册

更新时间：2026-08-17

## 1. 依据和使用边界

寄存器、状态位和控制字只以公司《第四版.doc》的前部码表为准。该文档后部
示例已确认有误，本手册和代码均不采用其中的示例帧。仓库中原来自行整理的
映射码表已删除。

公司表确定：从站地址为 `0x01`，串口为 115200、8 数据位、无校验、1 停止位；
`0x0000` 是 M1 命令状态字，`0x0001` 是 M2 命令状态字。公司表没有说明 M1/M2
对应车辆哪只轮，因此必须逐个点动并现场记录，不能先按左右轮猜测。

以下命令不使用 `printf`、`echo -e` 或临时脚本发送裸串口帧。

## 2. 每次实车操作前

必须同时满足：车辆牢固架空、四轮周围无人且无线缆或工具、操作者可立即硬件
断电、一次只测试一块板的一个电机。

前板 JP17 使用 `/dev/ttyS6`，后板 JP18 使用 `/dev/ttyS1`。先检查串口是否被
其他程序占用：

```bash
fuser /dev/ttyS6 /dev/ttyS1
```

没有输出表示当前未发现占用者；如有 PID 输出，先停止占用程序，不要强行测试。

## 3. 构建并运行软件测试

若车机工作区不是 `/home/rockchip/sand_rake_ws`，请替换第一行目录。

```bash
cd /home/rockchip/sand_rake_ws
source /opt/ros/humble/setup.bash

# 第一步：先编译团队共享消息包
CMAKE_BUILD_PARALLEL_LEVEL=1 colcon build --symlink-install \
  --executor sequential --parallel-workers 1 \
  --packages-select sand_rake_interfaces

# 第二步：编译基础控制包，并把包级、编译级并发都限制为 1
source install/setup.bash
CMAKE_BUILD_PARALLEL_LEVEL=1 colcon build --symlink-install \
  --executor sequential --parallel-workers 1 \
  --packages-select sand_rake_control

# 第二步成功结束后，再加载其结果并编译硬件工具包
source install/setup.bash
CMAKE_BUILD_PARALLEL_LEVEL=1 colcon build --symlink-install \
  --executor sequential --parallel-workers 1 \
  --packages-select sand_rake_hw_tools

source install/setup.bash
colcon test --executor sequential --parallel-workers 1 \
  --packages-select sand_rake_interfaces sand_rake_control sand_rake_hw_tools
colcon test-result --verbose
```

不要同时打开多个终端执行构建，也不要把构建命令并列到后台。每一步都必须等到
出现 `Summary: 1 package finished` 再继续；每个包内部最多启动一个编译任务。

只有三次构建和测试均通过后，才继续实车步骤。每次打开新终端，都要重新执行：

```bash
source /opt/ros/humble/setup.bash
cd /home/rockchip/sand_rake_ws
source install/setup.bash
```

## 4. 先看计划，不打开串口

下面是前板 M1、30 rpm、正转状态的 dry-run。它只打印计划，不打开串口：

```bash
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board front --motor M1 --direction forward --rpm 30
```

确认输出中有 `mode=DRY_RUN`、`serial_opened=NO` 和
`write_operations=NOT_EXECUTED`。

## 5. 只读检查前后板

前板：

```bash
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board front --status-only --device /dev/ttyS6 --execute \
  --confirm-wheels-off-ground --confirm-hardware-stop-ready \
  --confirm-exclusive-tty
```

后板：

```bash
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board rear --status-only --device /dev/ttyS1 --execute \
  --confirm-wheels-off-ground --confirm-hardware-stop-ready \
  --confirm-exclusive-tty
```

重点检查：

- `mode_raw=0x0001` 和 `status_mode_raw=0x0001`：FOLLOW；
- `alarm_code_raw=0x0000`：没有报警；非零时先停测；
- `bus_voltage_mv`：母线电压，单位 mV。公司表只给出低于 14 V 报警、高于
  50 V 报警，不应把这两个报警阈值当成设备的推荐工作电压；
- `m1_state_*`、`m2_state_*`：码表中的 M1/M2 命令状态；
- `m1_hall_count`、`m2_hall_count`：霍尔累计值；
- `m1_feedback_rpm`、`m2_feedback_rpm`：反馈转速；
- `program_version_raw`：程序版本原始值。

报警码：02 过温、03 母线过压、04 母线欠压、05 霍尔异常、08 堵转、14～20
主控外设异常。出现报警或读取失败，不执行点动。

## 6. 必要时逐板初始化

只在确有初始化需要且第 2 节全部条件持续满足时执行。前后板必须分开：

前板：

```bash
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board front --initialize --device /dev/ttyS6 --execute \
  --confirm-wheels-off-ground --confirm-hardware-stop-ready \
  --confirm-exclusive-tty
```

后板：

```bash
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board rear --initialize --device /dev/ttyS1 --execute \
  --confirm-wheels-off-ground --confirm-hardware-stop-ready \
  --confirm-exclusive-tty
```

工具依次清报警、清霍尔、设置 FOLLOW、将 M1/M2 减速时间设为 0，并在前后发送
双电机自由停车。结束必须看到 `post_init_mode_raw=0x0001` 和 `result=OK`。

## 7. 先发送自由停车

## 8. 四个电机逐个点动

一次只执行下面一条，默认先用 30 rpm、正转状态；每条完成后停下来记录实际
转动的轮、方向、是否有异响和状态输出，再执行下一条。

```bash
# 前板 M1
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board front --motor M1 --direction forward --rpm 30 \
  --device /dev/ttyS6 --execute --confirm-wheels-off-ground \
  --confirm-hardware-stop-ready --confirm-exclusive-tty

# 前板 M2
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board front --motor M2 --direction forward --rpm 30 \
  --device /dev/ttyS6 --execute --confirm-wheels-off-ground \
  --confirm-hardware-stop-ready --confirm-exclusive-tty

# 后板 M1
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board rear --motor M1 --direction forward --rpm 30 \
  --device /dev/ttyS1 --execute --confirm-wheels-off-ground \
  --confirm-hardware-stop-ready --confirm-exclusive-tty

# 后板 M2
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board rear --motor M2 --direction forward --rpm 30 \
  --device /dev/ttyS1 --execute --confirm-wheels-off-ground \
  --confirm-hardware-stop-ready --confirm-exclusive-tty
```

只有四个正转状态都记录清楚后，才把相应命令中的 `forward` 改为 `reverse` 逐个
验证。不要批量或并行执行，也不要因未转动就擅自提高到 100 rpm 以上或延长
300 ms。当前工具不提供四轮同时驱动命令，需先冻结实际轮位和方向。

记录表：

| 测试目标 | 实际物理轮 | 正转状态下实际方向 | 是否转动 | 报警/异响 | 备注 |
|---|---|---|---|---|---|
| front/M1 | 待填 | 待填 | 待填 | 待填 | |
| front/M2 | 待填 | 待填 | 待填 | 待填 | |
| rear/M1 | 待填 | 待填 | 待填 | 待填 | |
| rear/M2 | 待填 | 待填 | 待填 | 待填 | |

每次点动后重新执行第 5 节对应板的只读命令，保存状态、霍尔数和反馈转速。
`write=OK` 只表示 Linux 串口写入完成，不是车轮已转的证明。

## 9. 紧急停止和异常处理

硬件断电是首要停机手段。程序运行时可按 `Ctrl+C`，工具会尝试发送最终自由
停车，但通信失效时不能依赖软件停机。若串口仍可用，可再执行第 7 节对应板的
`--coast-only`；若通信不稳定、出现报警、异常声音或非目标轮动作，立即硬件
断电并停止后续测试。
