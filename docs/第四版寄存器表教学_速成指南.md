# 小车电机驱动与底盘控制：寄存器表速成指南

> 配套讲解：`第四版.doc`（公司寄存器表，前部码表）+ 本仓库代码。
> 本指南是**教学文档**，寄存器含义的唯一依据永远是公司《第四版.doc》的前部码表；
> 本指南若与码表冲突，以码表为准。码表后部示例（9.3 节）已被判定为错误，一律不用。

## 1. 先建立全局图：你手里有哪些东西

```
                        ┌──────────────────────────────┐
                        │   RK3576 车机 (ROS 2 Humble)  │
                        │  sand_rake_control            │
                        │  sand_rake_hw_tools           │
                        │  sand_rake_interfaces         │
                        └──────────────┬───────────────┘
                                       │ UART 115200 8N1 (Modbus RTU, 从站地址 0x01)
                ┌──────────────────────┼──────────────────────┐
                │                      │                      │
     ┌──────────▼──────────┐ ┌────────▼─────────┐
     │ 前轮驱动板 JP17      │ │ 后轮驱动板 JP18  │
     │ /dev/ttyS6           │ │ /dev/ttyS1       │
     │ 槽位 M1、M2          │ │ 槽位 M1、M2      │
     └──────────┬──────────┘ └────────┬─────────┘
                │                     │
          前轮×2（物理轮位未冻结）  后轮×2（物理轮位未冻结）
```

- 每块驱动板 = 一个 **Modbus 从站**，地址固定 `0x01`，管 **2 个电机槽位 M1、M2**。
- 公司表只定义"板内 M1/M2"，**没有定义 M1 是左轮还是右轮**——这是现场待确认项。
- 通信参数：波特率 115200、8 数据位、无校验、1 停止位（代码里 `rs232_transport` 强制校验这个组合，不满足直接报错）。

## 2. Modbus RTU 五分钟速成（看懂帧就够了）

Modbus RTU 报文 = **地址 + 功能码 + 数据 + CRC16**，字节流按序发送。

| 段 | 字节数 | 本板的值 |
|---|---|---|
| 从站地址 | 1 | `0x01` |
| 功能码 | 1 | `0x03` 读 / `0x06` 写单个 / `0x10` 本板自定义双电机写 |
| 数据 | 变长 | 见下文 |
| CRC-16/Modbus | 2 | 低字节在前（CRC_LO CRC_HI） |

CRC 算法固定为 CRC-16/MODBUS（多项式 `0xA001` 反向），`第四版.doc` 里给了 C 源码，
仓库 `modbus_rtu.hpp` 里 `crc16_modbus()` 是同一实现。发送方和接收方各自计算、
比对，不一致就丢弃——这是排查串口噪声/接错线最重要的手段。

一句话记法：**发出去之前算一遍 CRC，收回来以后也算一遍 CRC。**

## 3. 寄存器表详解（前部码表 = 唯一依据）

### 3.1 读寄存器表（功能码 0x03）——问板子"现在怎么样"

请求格式：`01 03 起始地址 寄存器个数 CRC`。每行都是读 1 个寄存器（`00 01`），
但可以一次连续读多个（本工具一次读 12 个：`01 03 00 00 00 0C 45 CF`）。

| 地址 | 含义 | 单位/取值 |
|---|---:|---|---|
| `0x0000` | M1 转速信息及状态字 | 高 12 位 = rpm，低 4 位 = 状态码 |
| `0x0001` | M2 转速信息及状态字 | 同上 |
| `0x0002` | M1 霍尔计数值高 16 位 | 与 `0x0003` 拼成 32 位计数 |
| `0x0003` | M1 霍尔计数值低 16 位 | |
| `0x0004` | M2 霍尔计数值高 16 位 | 与 `0x0005` 拼成 32 位计数 |
| `0x0005` | M2 霍尔计数值低 16 位 | |
| `0x0006` | M1 反馈转速 | rpm（电机实际转速反馈） |
| `0x0007` | M2 反馈转速 | rpm |
| `0x0008` | 当前模式 | 0=锁止、1=FOLLOW 跟随、2=自由 |
| `0x0009` | 母线电压 | 单位 100 mV（读回 270 = 27.0 V） |
| `0x000A` | 报警代码 | 0=无报警，其余见 3.4 |
| `0x000B` | 程序版本 | 当前实测 `0x0004` |

**状态字低 4 位（状态码）**，读和写共用同一套：

| 状态码 | 含义 |
|---|---:|---|
| 0 | 自由停止（Coast，断电滑行） |
| 1 | 正向运行 |
| 2 | 反向运行 |
| 3 | 刹车停止（Brake，锁死） |
| 4 | 减速到 0 停止（受减速时间影响） |

### 3.2 写寄存器表（功能码 0x06）——配置板子

请求格式：`01 06 地址 值 CRC`。

| 地址 | 含义 | 取值 |
|---|---:|---|---|
| `0x0005` | M1 减速时间 | 单位 100 ms，范围 0–2000 |
| `0x0006` | M2 减速时间 | 单位 100 ms，范围 0–2000 |
| `0x0007` | 清除 M1/M2 霍尔计数值 | 写 `0x0001` 清一次 |
| `0x0009` | 清除报警 | 写 `0x0001` 清一次 |
| `0x000F` | 设定模式 | `0x0000`=锁止、`0x0001`=FOLLOW、`0x0002`=自由 |

### 3.3 特殊功能码 0x10：一块帧同时控制 M1 和 M2

这是本板**自定义帧**，固定 8 字节，**不是**标准 Modbus"写多个寄存器"：

```
01 10  M1_H  M1_L  M2_H  M2_L  CRC_LO  CRC_HI
│  │   └── M1 控制字 ──┘  └── M2 控制字 ──┘
│  └ 功能码 0x10
└ 从站地址 0x01
```

**控制字编码（核心公式，务必背下来）：**

```
motor_word = (rpm << 4) | state        # rpm 只占低 12 位（0~4095），state 占低 4 位
```

公司表给出的速度示例（都是"高 12 位"）：

| 十六进制 | 十进制 rpm |
|---|---:|
| `0x032x` | 50 |
| `0x064x` | 100 |
| `0x164x` | 356 |
| `0x1F4x` | 500 |
| `0x3E8x` | 1000 |

组合示例（公司表原文）：`0x0321` = 50 rpm 正向运行，`0x0324` = 50 rpm 减速停止。
`0x03210641` = M1 是 0x0321（50 rpm 正转）、M2 是 0x0641（100 rpm 正转）。
`0x1F410642` = M1 是 0x1F41（500 rpm 正转）、M2 是 0x0642（100 rpm 反转）。

实际字节帧（CRC 已用仓库算法验证）：

```
双 Coast（四轮自由）     01 10 00 00 00 00 C0 09
M1 50rpm 正转、M2 Coast  01 10 03 21 00 00 90 47
M1 100rpm 正转、M2 Coast 01 10 06 41 00 00 90 95
M1 50 正转、M2 100 正转  01 10 03 21 06 41 53 D7
```

### 3.4 报警码表（读 `0x000A`）

| 代码 | 含义 | 处理 |
|---|---:|---|---|
| `0x02` | 温度超 85 °C | 停机检查使用温度 |
| `0x03` | 母线电压超 50 V | 停机检测电源及驱动电路 |
| `0x04` | 母线电压低于 14 V | 停机检测电源及驱动电路 |
| `0x05` | 霍尔信号报警 | 检查电机接线、霍尔线 |
| `0x08` | 堵转报警 | 检查接线、限流设置、是否堵转 |
| `0x14`–`0x20` | 主 MCU 外围电路异常 | 重新上电，仍报警则更换驱动器 |

### 3.5 五步初始化（工具 `--initialize` 的顺序）

| 步骤 | 操作 | 作用 |
|---|---:|---|---|
| 1 | 写 `0x0009=0x0001` | 清报警 |
| 2 | 写 `0x0007=0x0001` | 清霍尔计数 |
| 3 | 写 `0x000F=0x0001` | 设为 FOLLOW（跟随模式） |
| 4 | 写 `0x0005=0x0000` | M1 减速时间置 0 |
| 5 | 写 `0x0006=0x0000` | M2 减速时间置 0 |

工具在初始化前后各发一次双 Coast，最后重新读 `0x0008` 复核是否仍为 FOLLOW
（`0x0001`）。注意：**现有固件收到 0x06 后不回标准回显**，所以工具"不把回显当
成功条件"，用"最后读模式"来验证——这是实测固件行为，不是码表后部示例。

## 4. 五个易错点（看懂这五条才算真正入门）

1. **读地址和写地址不能互相推导。**
   `0x0008` 是"读模式"地址，`0x000F` 才是"写模式"地址。想当然地把读地址当写地址
   用是最大的坑。

2. **同一地址，读和写的含义可以完全不同**（取决于功能码）：

   | 地址 | 0x03 读 | 0x06 写 |
   |---|---|---|
   | `0x0005` | M2 霍尔低 16 位 | M1 减速时间 |
   | `0x0006` | M1 反馈转速 | M2 减速时间 |
   | `0x0007` | M2 反馈转速 | 清霍尔 |
   | `0x0009` | 母线电压 | 清报警 |

   所以代码里读状态和写配置是两套完全独立的常量，绝不能混用。

3. **`0x10` 是 8 字节自定义帧，不是标准 Modbus 写多寄存器 PDU。**
   它没有寄存器个数、没有数据长度字段；当前固件也不回 0x10 的响应。因此
   `write=OK` 只代表 Linux 串口把 8 个字节完整写进去了，**不代表电机转了**。

4. **状态字是"高 12 位转速 + 低 4 位状态"打包在同一个 16 位字里。**
   读 `0x0000`/`0x0001` 拿到的是打包字，要自己 `>> 4` 取转速、`& 0x0F` 取状态。
   霍尔是 `0x0002/0x0003`（M1）、`0x0004/0x0005`（M2）两个 16 位拼成 32 位：
   `count = (high << 16) | low`。

5. **码表后部的示例帧（9.3 节）是错的，一律不用。**
   例如其中把 `9C9C` 解释成"M1/M2 反向 100%"——低 4 位是 `C`，根本不在 0–4 的
   状态码里；有的示例帧还缺 CRC 字节。仓库代码、测试、实车记录均只采用前部码表。

## 5. 代码是怎么用这张表的（对照读）

- `src/sand_rake_control/include/sand_rake_control/modbus_rtu.hpp`
  定义功能码常量：`kReadHoldingRegisters=0x03`、`kWriteSingleRegister=0x06`，
  以及 `crc16_modbus()`、`build_read_holding_registers_request()`、
  `build_write_single_register_request()`——就是 3.1/3.2 帧的构造器。

- `src/sand_rake_control/src/modbus_rtu_client.cpp`
  完整的一次"读"事务：先丢弃串口残留字节 → 发请求 → 按响应长度读回 → 校验
  CRC/地址/功能码 → 返回寄存器值数组和耗时。`ModbusRtuClient` 用原子锁保证同一
  时刻只有一个事务。

- `src/sand_rake_hw_tools/src/small_car_four_wheel_jog_once.cpp`（实车工具，对照表最直观）：
  - `kSlaveAddress = 0x01`、`kDualMotorFunction = 0x10`；
  - `kStatusStartRegister = 0x0000`、`kStatusRegisterCount = 12` → 一次读
    `0x0000~0x000B` 全部 12 个寄存器（`01 03 00 00 00 0C ...`）；
  - `kModeReadRegister = 0x0008`：动作前读模式，要求 `0x0001`（FOLLOW）；
  - `kInitializationSteps`：就是 3.5 的五步；
  - `pack_motor_word(rpm, state)`：`(min(rpm,0x0FFF) << 4) | (state & 0x0F)` ——
    控制字公式的代码实现；`build_dual_motor_frame()` 拼 `01 10 M1 M2 CRC`；
  - `build_coast_frame()`：两个字都 `0x0000` → `01 10 00 00 00 00 C0 09`；
  - `print_full_status_values()`：把 12 个寄存器按表解析成可读输出
    （霍尔高 16 位 << 16 | 低 16 位；母线电压 × 100 = mV；状态码 0–4 → 字符串）。

- `src/sand_rake_control/src/rs232_transport.cpp`
  强制 115200/8N1，参数不匹配直接拒绝打开串口（对齐公司表第 9.3 节前部说明）。

## 6. 动手练习（先自己做，再看答案）

**练习 1**：你要让 M2 以 100 rpm 反转、M1 保持 Coast，写出完整的 8 字节 `0x10` 帧。

**练习 2**：`--status-only` 读回 12 个寄存器，前 6 个值是：
`0x0000, 0x0000, 0x0000, 0x03E8, 0x0000, 0x0014`。
请回答：M1 状态是什么？M1 霍尔计数是多少？

**练习 3**：读 `0x0008` 得到 `0x0002`，读 `0x000A` 得到 `0x0008`，读 `0x0009`
得到 `0x010E`。分别是什么意思？此时能不能点动？

**练习 4**：下面这段记录里，`0x0641` 为什么是"100 rpm 正转"？（用公式拆开算）

```
01 10 06 41 00 00 90 95
```

<details>
<summary>答案（先自己算再看）</summary>

- **练习 1**：M2 控制字 = `(100 << 4) | 2 = 0x0642`；M1 Coast = `0x0000`。
  帧 = `01 10 00 00 06 42` + CRC。用仓库 `crc16_modbus` 算出 CRC 后拼上即可
  （自己动手在代码里加一行测试，或按第 2 节算法手算验证）。
- **练习 2**：`0x0000` = rpm 0、状态 0 = 自由停止；M1 霍尔 =
  `(0x0000 << 16) | 0x03E8 = 1000` 次。
- **练习 3**：模式 `0x0002` = 自由模式（不是 FOLLOW）；报警 `0x0008` = 堵转；
  母线电压 `0x010E` = 270 × 100 mV = 27.0 V。**不能点动**——工具要求模式 FOLLOW
  且报警为 0 才放行。
- **练习 4**：`0x0641` → `>> 4` 得 `0x064` = 100（rpm），`& 0x0F` 得 `1`（正转）。
  所以是 M1 100 rpm 正转（M2 字 `0x0000` = Coast）。
</details>

## 8. 一句话总结

> 小车 = 两块 Modbus 从站板，各管 M1/M2；读用 `0x03` 按表取状态，
> 写用 `0x06` 配置/清错，跑起来用 `0x10` 一帧带两个控制字；
> 控制字永远是 `(rpm<<4)|state`，地址含义随功能码变，
> 唯一依据是《第四版.doc》前部码表，其余全是安全边界。
