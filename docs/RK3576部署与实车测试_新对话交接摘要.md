## 4. 公司表中的寄存器与控制帧

### 4.1 `0x03` 读取

| 地址 | 公司表定义 |
|---:|---|
| `0x0000` | M1 命令转速/状态字 |
| `0x0001` | M2 命令转速/状态字 |
| `0x0002～0x0003` | M1 霍尔累计值高/低 16 位 |
| `0x0004～0x0005` | M2 霍尔累计值高/低 16 位 |
| `0x0006` | M1 反馈转速 rpm |
| `0x0007` | M2 反馈转速 rpm |
| `0x0008` | 模式：0 锁定、1 FOLLOW、2 自由 |
| `0x0009` | 母线电压，单位 100 mV |
| `0x000A` | 报警码 |
| `0x000B` | 程序版本 |

命令状态字高 12 位为 rpm，低 4 位状态为：0 自由停车、1 正转、2 反转、
3 刹车停车、4 减速到零。

### 4.2 `0x06` 单寄存器写

| 初始化顺序 | 操作 | 地址和值 |
|---:|---|---|
| 1 | 清报警 | `0x0009=0x0001` |
| 2 | 清霍尔 | `0x0007=0x0001` |
| 3 | 设置 FOLLOW | `0x000F=0x0001` |
| 4 | M1 减速时间置 0 | `0x0005=0x0000` |
| 5 | M2 减速时间置 0 | `0x0006=0x0000` |

减速时间单位为 100 ms，范围 `0～2000`。读取和写入地址不能互相推导：
`0x0008` 是模式读取地址，`0x000F` 是模式设置地址。

现有固件通信路径发送 `0x06` 后不读取或校验标准回显，因此当前工具也不把
严格回显作为写入成功条件，并在初始化结束后读取模式复核。此处描述实现行为，
不是采用《第四版.doc》后部示例。

### 4.3 自定义 `0x10` 双电机控制

该帧固定为 8 字节，不是标准 Modbus 写多个寄存器 PDU：

```text
01 10 M1_H M1_L M2_H M2_L CRC_LO CRC_HI

motor_word = (rpm << 4) | (state & 0x0F)
state: 0=自由停车, 1=正转, 2=反转, 3=刹车停车, 4=减速到零
```

当前实现不读取 `0x10` 响应。工具输出 `write=OK` 只证明 Linux tty 接收了
完整发送数据，不等于驱动板已经执行。

## 5. 当前小车工具及能力边界

工具：

```text
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once
```

已有约束：

- 只允许 `front/rear` 和 M1/M2；
- 前板固定 `/dev/ttyS6`，后板固定 `/dev/ttyS1`；
- 默认 dry-run；
- 真机执行要求显式确认架空、硬件停机手段和 tty 独占；
- 点动只允许 30/60/100 rpm，固定 300 ms；
- 动作前、动作后和信号中断时发送双电机 Coast；
- 点动时另一槽位保持 Coast；
- 动作前读取 `0x0008` 并要求 FOLLOW；
- 点动后 50 ms 从 `0x0000` 起读取 M1/M2 状态字；
- `--status-only` 读取 `0x0000～0x000B` 全部 12 个状态寄存器。

只读状态命令模板：

```bash
ros2 run sand_rake_hw_tools small_car_four_wheel_jog_once \
  --board front --status-only --device /dev/ttyS6 --execute \
  --confirm-wheels-off-ground \
  --confirm-hardware-stop-ready \
  --confirm-exclusive-tty
```

专用初始化入口为 `--initialize`。它在只读确认 FOLLOW 后先发送双 Coast，再按
第 4.2 节顺序发送五条 `0x06`，最后发送双 Coast，并在短暂静默和清空延迟字节
后重新读取 `0x0008` 复核 FOLLOW。工具不要求标准 `0x06` 严格回显；发送失败或
信号中断时会停止后续初始化步骤并尝试最终 Coast。

## 6. 已有实车证据

1. 前、后板收到双 Coast 帧 `01 10 00 00 00 00 C0 09` 后，原先锁死的
   四轮可以用手自由转动，证明 state 0 的机械效果为 Coast。
2. 30、60、100 rpm 的受控点动均未观察到轮胎转动。
3. front/M1 发送 100 rpm/state 1，即 `01 10 06 41 00 00 90 95`，50 ms 后
   从 `0x0000` 起读取两个状态字得到：

   ```text
   state_slot_0_raw = 0x0000
   state_slot_1_raw = 0x0641
   ```

   `0x0641=(100<<4)|1`。这是历史上“向 M1 发送、M2 状态字出现命令”的异常
   现象，不能用来推翻公司表规定的寄存器顺序，后续应按异常回读继续诊断。
4. 所有动作测试结束时均发送最终 Coast；用户随后确认四轮可自由转动。
5. 2026-08-16 车机重启后，两板状态字一度均为 `0x0003`（Brake）。
6. 用户明确授权并持续确认车辆架空后，前、后板均完成五步初始化，随后读取
   `0x0008=0x0001`，两状态字均为 `0x0000`（Coast）。
7. 初始化后执行 front/M1、30 rpm/state 1、300 ms 点动，状态区再次读回
   `state_slot_1_raw=0x01E1`；现场物理轮观察结果尚未记录。

## 8. 安全边界

- 真机动作时车辆必须持续架空，轮旁无人、无线缆或工具。
- 操作者必须在现场观察，并能立即硬件断电。
- 一次只测一块板的一个槽位，另一槽位始终 Coast。
- 串口、模式、帧写入或状态读取出现异常时立即停止并尝试最终 Coast。
- 在视觉确认前，不把候选轮位或方向写入正式 YAML。
- 不因无动作擅自超过 100 rpm 或延长 300 ms。
- 用户不在现场时，不执行真机写操作。
